# Manual setup and release checklist

## Before approving the pull request

- [ ] Confirm the current studio address and Google Maps pin, public phone and email, workshop languages, durations and approved photography. The site displays Yonatan Ratosh 2, Tel Aviv–Yafo. If plans change, update `lib/site.ts` and both business listings together on the effective date.
- [ ] Verify indoor capacity by workshop format and equipment, and off-site capacity by venue and format. Approve any edits to the homepage’s existing “10-50+ participants” card and the FAQ’s “All workshops are private” wording separately.
- [ ] Read both landing pages in English and Hebrew in a protected preview. Approve the group inquiry’s email handoff and deliverability. Confirm photo permissions for the group page.
- [ ] In Contentful, confirm the `myBlogs` model and exact English and Hebrew delivery locale codes. Set `CONTENTFUL_EN_LOCALE` or `CONTENTFUL_HE_LOCALE` only if they differ from `en-US` and `he`. Keep the existing delivery credentials server-only. Enable localized title, rich text, slug, excerpt and image description fields as applicable. Publish a test translation to the review environment and confirm the two slugs, alternate URLs, and language switcher. [Contentful localization](https://www.contentful.com/developers/docs/references/content-delivery-api/localization/)
- [ ] Verify that the six existing English articles remain published with their original slugs. Confirm the attribution for each entry before setting an author. Add useful asset descriptions and update workshop links with the CMS editor.
- [ ] In Monkeybook, check the shared private-workshop order URL from all six workshop detail pages and the separate community destination in English and Hebrew. Verify selected product, duration, location, prices shown by the provider, payment, confirmation, cancellation and rescheduling with a provider test booking. Confirm the September Blend Lab dates are archived. Record the verified individual links if different products require them.
- [ ] Review the policy’s third-party service references, retention and cancellation terms with the owner. Align the approved policy with actual hosting, analytics, booking and payment providers. Approve a Hebrew translation before giving it its own canonical.
- [ ] Send one controlled test inquiry from both language pages and check delivery to the published inbox and reply handling. No email provider connection is required for the email-app handoff. If server-side delivery is later approved, verify the sender domain and SPF, DKIM and DMARC, and plan validation, abuse protection, retention and delivery acknowledgements before switching the form.

## Hosting and indexing

- [ ] Keep the production domain at `www.concept-coffee.com`. In Vercel, confirm whether apex already redirects at the domain layer. Confirm an HTTPS 308 to the same path and query on www from apex, and no redirect loop or blanket redirect on preview domains. Check `/` with both language preferences.
- [ ] Confirm built and deployed `/robots.txt` and `/sitemap.xml` return 200 on www. Check HTML canonicals, language alternates and OG metadata for both languages, and validate sample JSON-LD with Schema.org’s validator. Watch for `noindex` on approved live pages.
- [ ] Confirm Vercel preview deployment protection and `X-Robots-Tag: noindex`. Keep the environment variable `PUBLISH_AUDIENCE_PAGES` unset in production until both audience pages are approved. Set it to `true` for the approved deployment and confirm all four URLs appear in the sitemap and that the directory and corporate links are present. For a local production-build review, set `SHOW_AUDIENCE_DRAFTS=true` at build time. Review drafts remain noindex.
- [ ] Check Vercel Firewall, any upstream CDN and bot protection, including verified crawler access for Google, Bing, OpenAI, Anthropic and Perplexity. Compare actual crawl logs and published verification methods to user-agent responses. Keep rendering assets available.
- [ ] In Google Search Console, verify the domain with DNS. Submit the www sitemap and inspect both homepages, one workshop per language, an English article, and each approved audience page. Review indexing and reciprocal locale mappings after recrawl. [Search Console ownership verification](https://support.google.com/webmasters/answer/9008080)
- [ ] Verify the site and submit the same sitemap in Bing Webmaster Tools. Inspect redirect handling, discovery and crawl activity. [Bing Webmaster Tools](https://www.bing.com/webmasters/about)
- [ ] Claim or verify Google Business Profile and Bing Places. Align business name, studio address, public phone, website, category and applicable hours with the owner. Add actual studio and teaching photos, use the correct map pin and consolidate duplicate listings. Check a relevant local visitor directory if it accepts the verified listing. [Google Business Profile editing](https://support.google.com/business/answer/3039617) · [Bing Places](https://www.bingplaces.com/)

## Measurement

- [ ] Confirm Vercel Web Analytics and Speed Insights are enabled in the correct project. Confirm the project plan supports custom events and validate ingestion after an owner-approved preview or release. [Vercel custom events](https://vercel.com/docs/analytics/custom-events) · [Vercel Speed Insights](https://vercel.com/docs/speed-insights)
- [ ] Track weekly Search Console and Bing impressions, clicks, click-through rate and indexing by query, locale and landing page. Record a 28-day pre-launch baseline if available, then compare at comparable seasonal windows.
- [ ] Track workshop detail visits and the `booking_link_clicked`, `visitor_inquiry_clicked`, `group_inquiry_clicked`, `group_email_draft_requested` and `corporate_inquiry_clicked` events. The analytics payloads use event context, locale and destination only. Compare actual inquiries to these indicators using aggregate owner-side totals. Add a distinct operator inquiry indicator if that page launches.
- [ ] Confirm with Monkeybook whether a supported completed-booking event or aggregate report can be reconciled with workshop and locale. Avoid sending names, dates requested, email addresses, phone numbers, or notes to any analytics platform.
- [ ] Review LCP, INP and CLS by route and device where field data is available. Inspect referral hosts for observable AI-assisted visits and record direct or unattributed traffic separately in reporting. Dashboards and provider exports determine which outcomes can be measured.
